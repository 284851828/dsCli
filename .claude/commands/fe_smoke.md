对**前端新需求**做 AI 冒烟：读需求 → 出冒烟用例（需求本身有疑点才请人确认） → 用浏览器真实操作页面，对照需求判定 → 分诊 → 出带证据的报告。
需求与实现不一致是**执行阶段**要报的缺陷，执行前不拿现状比对需求。
**只测本次需求的新功能**，不做回归、不测视觉还原度、不改业务代码。本期只支持 wowebui。
Codex 入口：`.agents/skills/fe_smoke/SKILL.md`（只写 Codex 下的差异；改本文件中的提问、子代理、工具名相关内容时，同步检查它）。

> 用法：`/fe_smoke <需求来源> [--url <测试地址>] [--resume] [--yes] [--assume-default] [--only SM-01,SM-03]`
> 例：`/fe_smoke req_7078405903`　`/fe_smoke docs/xxx/需求.md`　`/fe_smoke req_7078405903 --resume`　`/fe_smoke req_7078405903 --url <另一个测试地址>`（临时换环境）

## 参数

| 参数 | 默认 | 作用 |
|---|---|---|
| `<需求来源>` | 必填 | `req_<id>`（fsprm 需求）/ 飞书需求单 URL / 本地 md 路径 |
| `--url` | 配置中的地址 | 临时改测另一个 wowebui 站点根地址（只对本次生效，不改配置）。不带就用 `config/fe-smoke.env` 的 `FE_SMOKE_WOWEBUI_BASE_URL`，不提问 |
| `--resume` | 关 | 人工离线回答待确认项或填完测试数据后继续：有未回写的 `00-待确认项.md` 时从 S1.5 回写开始，否则从 S2 读测试数据回答开始，跑到报告。`<OUT>` 下已有 `02-冒烟用例.md` 但没带本参数时，同样按 `--resume` 处理（不重做 S1） |
| `--yes` | 关 | 跳过确认点②（用例确认）。**有待确认项时确认点①永远不跳**；测试数据有 C/D 类未提供时仍会停 |
| `--assume-default` | 关 | 未回答的待确认项按「AI 默认假设」执行，结果标「✅（基于假设 Q-xx）」 |
| `--only` | 全部 | 只执行指定用例（复测用）。被指定用例「依赖」的用例：其共享数据仍存在（只读查到）就不重跑，否则一并执行 |

## 固定常量

- **底座** `tools/fe-smoke/`（用法见其 README）；**配置** `config/fe-smoke.env`（人工填写，🔴 不读出、不回显其中的值）
- **测试地址** `<URL>`：用户在 `config/fe-smoke.env` 配置的地址；带 `--url` 时以它为准。🔴 不就测试地址向用户提问。不核对分支 / 版本，结论一律以 `<URL>` 上看到的页面为准，报告头写明 `<URL>`
- **浏览器** Playwright MCP（`mcp__playwright__*`），由 preflight 生成的注入脚本自动带登录态
- **提问方法论** `tools/feishu-prd-review/docs/03-review-method.md`
- **默认规则** `tools/fe-smoke/docs/默认规则.md`（PRD 没写的通用细节按它出预期，不再提问；S1 开始前必读）
- **用户只看三份产物**：`00-待确认项.md`（有疑点才有）、`02-冒烟用例.md` + `02a-测试数据.md`、`03-冒烟报告.md`。不生成需求理解文档
- **用例与报告同时出 md + HTML**：`02-冒烟用例.md`、`03-冒烟报告.md` 每次写入或回写后（S1.2、S1.4 合并、S1.5/S2 回写、S3 回写、S6），立即运行 `node tools/fe-smoke/src/render-html.mjs <md 路径>...`，在同目录生成同名 `.html`（表格布局、结果徽标、目录、证据截图链接、结果筛选，自包含，可直接用浏览器打开或转发）。🔴 md 是唯一数据源：只改 md 再重新生成，**不手改 HTML**；脚本退出码非 0 时把报错告诉用户，md 照常交付
- **向用户提问的方式**（确认点①②通用）：
  - **默认在对话里用 `AskUserQuestion` 选择题收集回答**，不让用户编辑 md。每项一题，每次最多 4 题，多于 4 项分批问；推荐项放第一个并标「（推荐）」（待确认项 = AI 默认假设；B 类 = 建议值），另给一个「不提供 / 暂不回答」选项（对应用例标 ⚠️ / ⏸）；需要自由输入的值（C 类）让用户选「Other」填写。问题文本要能单独看懂：写清编号、要什么、影响哪些用例
  - 🔴 D 类（凭证）不进选择题，只提示用户把对应键写进 `config/fe-smoke.env`，回复「已填」后检查键是否非空
  - md 是**记录**：AI 先写好（「你的回答」留空），拿到回答后由 AI 回写，供 `--resume` 和事后追溯
  - 用户也可以直接在对话里一句话回答（如「D-01 按建议，D-02 否」），或离线编辑 md 后 `--resume`，三种方式等价
  - 待问项超过 8 项时，先问用户是在对话里逐批回答还是离线填 md
- **用例格式与“预期可判定”规则** 沿用 `.claude/commands/req_testcase.md`
- **产物目录** `<OUT>`：
  - fsprm 需求 → `docs/req/req_<id>/fe_smoke/`
  - 其他 → `temp/fe-smoke/<YYYY-MM-DD>-<需求简称>/`
  - 截图、网络日志放 `<OUT>/evidence/`（已 gitignore）
  - 分组执行时各组结果放 `<OUT>/runs/`（过程文件，供 S6 汇总与追溯，不要求用户看）
- 🔴 **业务代码只读**：`git -C code/wowebui show origin/<分支>:<文件>`。禁止修改 `code/` 下任何文件

## 🔴 红线（任何阶段都适用）

1. **期望只来自需求原文、产品回复、默认规则或人工已回答的待确认项**，不来自现状或实现。不得为让用例通过而改预期、放宽断言；执行中发现实现与需求不一致，判 ❌ 照实报告，不回头改预期、不改成提问
2. **不改业务代码**。发现缺陷只报告
3. **每个 ✅ 都要有证据**：截图文件名 + 断言描述（看到了什么）。没有证据的 ✅ 等于没测
4. **不做回归**：用例之外的页面不测；顺带看到的问题写进「附带发现」，不计入结果
5. **写入数据加前缀**：新建/编辑时可自由填写的文本字段一律以 `FE_SMOKE_DATA_PREFIX`（默认 `AI冒烟_`）开头；不删除、不修改非本次创建的数据（例外：`temp/fe-smoke/数据台账.md` 中登记为本工具自建的数据，可按 S2「台账复用」规则复用）
6. **不能自动的如实标「需人工」**，不假装跑了
7. **凭证不出现在任何产出中**。MCP 返回内容里的 `<secret>` 占位符保持原样，不要尝试还原。🔴 `browser_network_request` **必须带 `part`**（`request-body` / `response-body`），不取完整详情：完整详情含 `x-token` 等请求头，凭证会进入上下文

## 步骤

### S0 预检（失败即停）

```bash
node tools/fe-smoke/src/preflight.mjs              # 用配置中的地址
node tools/fe-smoke/src/preflight.mjs --url <地址>  # 带了 --url 时
```

`<URL>` 取预检输出第一行「配置：站点 …」中的地址，写进用例与报告头。`--resume` 时沿用用例文件头记录的 `<URL>`（与预检地址不同时在报告「环境备注」中注明）。

- 退出码非 0 → **停下**，把控制台输出的 ❌ 项原样告诉用户（常见：没建 `config/fe-smoke.env`、密码错、token 过期、环境不通）
- 通过后若本会话中 MCP 浏览器已打开过，先调 `browser_close`，让新登录态生效
- ⚠️ 项（如首页有 console 报错）记入报告「环境备注」，不阻断

`--resume` 时同样先跑预检（token 可能已过期）。

### S1 读需求，出冒烟用例

目标：**只依据需求**写出可执行的冒烟用例。需求与实现是否一致，留到 S3/S4 执行时去看。

🔴 **本步不看现状**：不打开被测页面，不读业务代码，不拿实现来定预期，也不拿实现去「核对」需求。实现和需求不一样，是执行阶段要报的缺陷，不是执行前要问用户的问题。
🔴 **不写《需求理解确认单》**：理解直接体现在用例里，用户只看用例。

#### S1.1 读全

按顺序读，读全再动笔；缺哪项在用例文件头的「资料清单」里注明“未读到”：

| # | 读什么 | 说明 |
|---|---|---|
| 1 | PRD 正文 | `req_<id>`：`docs/req/req_<id>/prd/<最新日期>/prd.md`；飞书 URL：先跑 `/prd_download` 再读；本地 md：直接读 |
| 2 | PRD 图片 | 同目录 `img/`（或正文引用的图片目录），**逐张看**正文引用到的图。交互、字段、按钮、文案常常只在图里 |
| 3 | 已澄清内容 | `01-AI分析_r*.md`、`04-产品回复_r*.md`（产品回复是需求的一部分）；已有 `05-自测用例.md` 时读其中前端用例 |
| 4 | Figma | PRD 里有 Figma 链接时用 Figma MCP 读，重点看空态 / 错误态 / 禁用态与文案 |
| 5 | 业务知识 | `docs/knowledge/索引.md` 中相关模块；PRD 里的业务名词要能在这里找到含义 |

非前端的内容（定时任务、消息消费、纯后端规则）、外部系统同步、视觉还原度不出用例，在用例文件「不在本次冒烟范围」中列出（默认规则 R-7）。

#### S1.2 出用例 `<OUT>/02-冒烟用例.md`

每个功能点 **1 条主路径 + 关键分支**（分支来自状态、权限、边界、文案），不追求穷举。

```markdown
# <需求标题> —— 冒烟用例

> 来源：<需求来源>　测试地址：<URL>　生成：<YYYY-MM-DD>　模型：<model>
> 资料清单：PRD ✅ / 图片 N 张 ✅ / 产品回复 ✅ / Figma ❌ 无链接
> 不在本次冒烟范围：<后端规则、外部同步、视觉…及原因>

### SM-01 <一句话场景>（功能点：<一句话>）
- **入口**：wowebui / <路由或菜单路径>（按需求写，执行时再定位）
- **前置**：<账号、数据、配置；需要的测试数据写 D-xx 编号（见 S2）>
- **依赖**：<无 / 用到哪条用例产出的共享数据，如「SM-02 → 仓A」>
- **写入影响**：<无写入 / 可撤销 / 不可撤销 / 影响他人>（判定见下方「写入影响」）
- **步骤**：1. … 2. …
- **预期**：<可判定结果>
- **依据**：PRD 3.2「<原文摘录>」 / 图 5「<图中文字>」 / 默认规则 R-x.x / 待确认项 Q-xx
- **可自动**：✅ / ❌ 需人工（原因） / ⏸ 待确认（Q-xx）
```

依据规则（写死，不许变通）：
- 每条预期都要写依据，而且只能是：**原文摘录**（引号内原话，或图号 + 图中文字）、**默认规则编号**、**已回答的待确认项**。三者都写不出 → 这条预期不成立，要么删掉，要么转成 S1.3 的待确认项
- 🔴 依据里**不得出现**「现状」「实现」「代码」「截图 now-xxx」
- PRD 没写、默认规则也没覆盖、答案又不影响任何用例结论的细节：不出预期，执行时看到什么记 👁 观察（报告中归入「建议优化」），不判 ✅/❌
- 原型图只是示意的部分（弹窗 / 抽屉 / 面板形态、按钮摆放、提示条样式）：按默认规则 R-2.7、R-6.1，不作为断言；但 **PRD 正文写明的字段、列、操作、规则**都要出预期（R-3.5）

**写入影响**（每条用例都标，S2 据此问用户、S6 据此写清理状态）：

| 级别 | 含义 | 处理 |
|---|---|---|
| 无写入 | 只查询、只看 | — |
| 可撤销 | 写入后能在页面上改回或删除（停用后再启用、绑定后解绑、可删除的数据） | 用例末尾加「复原」步骤，执行完即复原 |
| 不可撤销 | 写入后无法删除（如实体不提供删除、写入外部系统） | 尽量少建：负向校验（格式、空格、超长）**优先放到「修改自建数据」中测**，只有「新增」独有的校验才在新增里测；必须新建的数据在「共享数据」中复用 |
| 影响他人 | 改动非本次创建的数据，或全局唯一项（默认项、全局开关、店铺/账号绑定关系）会影响他人 | 🔴 一律进 S2 的 C 类，由用户决定能否做；不能做的标 ⏭ 需人工 |

文末附两张表：
- **共享数据**：被多条用例复用的自建数据 → 由哪条用例创建 → 哪些用例使用 → 写入影响。依赖链不要超过 3 层；后续用例依赖的数据尽量由一条「准备用例」统一创建
- **覆盖表**：PRD 每个功能点 / 规则 → 覆盖它的用例编号；没有用例覆盖的写明原因

#### S1.3 待确认项（只问需求本身）

出用例时遇到下面几类，才进待确认项：

| 进待确认项 | 不进（怎么处理） |
|---|---|
| PRD 前后矛盾；PRD 正文与图冲突 | 需求与现状 / 实现不一致 → **执行时判 ❌「需求不一致」**（S5） |
| PRD 没写的业务规则（唯一性、互斥、权限、状态流转），而且不同答案会让某条用例预期不同 | 默认规则已覆盖的 → 按规则出预期，依据写 R-x.x |
| 业务名词在需求和知识库里都找不到定义，影响预期 | 不影响结论的细节 → 执行时记 👁 观察 |
| | 原型图里的**文案 / 提示小字**与正文冲突，而正文表述一致、或原型声明「以 PRD 为准」→ 按正文出预期，冲突记报告「附带发现」 |
| | 某个答案在界面上**无法落地**（如问「按店铺还是按租户唯一」，但表单里根本没有店铺字段）→ 不是有效分歧，按能落地的答案出预期 |

疑点排查维度：状态、角色权限、数据边界、文案、联动、冲突、名词（方法见 `03-review-method.md`）。🔴 **不凑数**：没有疑点就写「无」。

**结论检验**：每条待确认项都要能写出「答 A → 预期 X；答 B → 预期 Y」，而且 X、Y 都要能在页面上操作和判定。两种答案预期相同，或其中一种在界面上无法落地，就不是待确认项。

有待确认项时写 `<OUT>/00-待确认项.md`：

```markdown
# <需求标题> —— 待确认项

> 回答方式：AI 会在对话里逐条提问，你点选即可，回答由 AI 回写到本文件。也可以直接改下面的「你的回答」行（同意默认假设写「按默认」），再执行 `/fe_smoke <需求来源> --resume`。
> 未回答的问题，对应用例不执行（除非使用 --assume-default）。

### Q-01 <一个可直接回答的问题>
- 出处：PRD 3.2 / 图 5　来源：自查
- AI 默认假设：<默认假设>
- 影响：答 A → SM-03 预期 X；答 B → 预期 Y
- 你的回答：
```

每条问题必须能直接回答（是/否、选一个、给个值），定位到具体章节或图。同根问题合并成一条；超过 5 条时逐条复查能否合并或降级。相关用例标 ⏸。

#### S1.4 独立复核（子代理）

用 Agent 工具起一个**新的**子代理（不要 fork，避免它继承你的推理）。prompt 只给：PRD 及图片路径、产品回复路径、默认规则路径、`02-冒烟用例.md` 路径（有 `00-待确认项.md`、`02a-测试数据.md` 时一并给；没有 `02a` 时在 prompt 里说明「D-xx 是测试数据编号，清单在 S2 才生成，不在复核范围」），要求它：

> 你是冒烟用例复核员。只对照需求原文检查这份用例，不要假设作者是对的，不要打开被测页面或读业务代码。找出：
> ① 需求里有、用例没覆盖的功能点或规则；② 预期与原文不一致，或依据摘录不成立、不在原文中的；③ 依据引用了现状 / 实现的；
> ④ 应该提问却没提的待确认项：只列需求**自身**矛盾或缺失、且答案会改变某条预期的，写出「答 A → 预期 X；答 B → 预期 Y」。需求与实现不一致不算（那是执行时的缺陷）；默认规则已覆盖的不算；
> ⑤ 待确认项里应该删掉、降级或合并的。每条给出原文出处。没有问题就说没有，不要凑数。只读，不修改任何文件。

逐条判断后合并：成立的改进用例；新增疑点按 S1.3 判断是否进待确认项（「来源」列写「复核」）。不采纳的在用例文件末尾「复核意见处理」中写明理由。

#### S1.5 确认点①（有待确认项才停）

- **待确认项 K > 0**：告诉用户用例 N 条、待确认项 K 条及 `00-待确认项.md` 路径，然后按「向用户提问的方式」用 `AskUserQuestion` 逐条提问（选项：AI 默认假设（推荐）/ 另一种答案 / 暂不回答）。拿到回答即按下面「回写」处理并继续，不必等 `--resume`；用户暂不回答的保持 ⏸。用户选择离线填写时**停止本次执行**
- **K = 0**：不停，直接进入 S2，用例与测试数据在确认点②一起交给用户看

回写（对话中拿到回答，或 `--resume` 进入时）：
- 读对话里的回答（或 `00-待确认项.md` 的「你的回答」），先回写到 `00-待确认项.md`，再，回写到对应用例的预期与依据（依据写「待确认项 Q-xx 回答：<原话>」），⏸ 改为 ✅
- 回答与默认假设不同 → 说明 AI 理解有偏差：属于通用细节的，把正确做法补进 `tools/fe-smoke/docs/默认规则.md`（并在其「变更记录」写一行）；属于本 skill 流程或判断方法的，直接改本文件对应步骤
- 未回答的：有 `--assume-default` 则按默认假设出预期（依据写「默认假设，未经确认」）；否则保持 ⏸

### S4 执行（MCP 直驱）

逐条用例执行，每条都按这个节奏：

1. `browser_navigate` 到入口（hash 路由：`<URL>#/<路由>`）
2. 按步骤操作（`browser_click` / `browser_type` / `browser_fill_form` / `browser_select_option` 等），每步前用 `browser_snapshot` 定位元素
3. **关键步骤截图**：`browser_take_screenshot`，文件名 `SM-01-<序号>-<动作>.png`
4. 在预期出现的位置用 `browser_snapshot` / `browser_wait_for` 取得实际结果，**逐条对照预期**写下“看到了什么”
5. **提交类操作**（保存、删除、启停、绑定等写操作）：用 `browser_network_requests` 找到该次请求，再用 `browser_network_request`（🔴 带 `part=request-body` / `part=response-body`，见红线 7）取请求体与响应，记下方法 + 路径、请求体关键字段、响应状态与业务码 / 新建 id。这是判定「是否落库」的**主证据**，提示条只是辅证（提示几秒就消失、可能截不到）。⚠️ 刷新 / `browser_navigate` 后网络列表会清空，要先取完请求体再刷新。等待响应超过 10 秒的记 👁 观察（写明耗时）
   - **用列表接口核对**：以下情况不要只看页面，取列表接口的响应体核对（把每页条数调到最大，保存到 `temp/fe-smoke/mcp/` 后用 `node -e` 统计，只记统计结果）：① 全局唯一类规则（「最多一个默认」「同一店铺只能绑一个」），要数**全量**数据，不能只看第一页；② 页面上缺字段 / 缺列时，确认接口是否已返回该字段，用于分诊（接口有、页面没有 → 初判前端）
6. 底线检查：`browser_console_messages`（error 级）与 `browser_network_requests`（xhr/fetch 的 4xx/5xx）
7. 写入影响为「可撤销」的，按用例的复原步骤复原并截图
8. 记录：结果、证据文件名、实际看到的内容、接口证据、底线检查结论

- 弹窗确认（a-modal / popconfirm）：确认按钮在弹出层里，文案多为「确定」「确认」
- 成功/失败提示是 `.arco-message`，几秒后消失，操作后要**立即** snapshot 或截图

### S5 失败分诊

| 分类 | 判定依据 | 处理 |
|---|---|---|
| 操作问题 | 元素没点到、时机不对；页面本身行为正常 | 换定位方式重试，**同一用例最多 2 次**，仍不行标「⚠️ 阻塞：自动化操作失败」并写明卡在哪一步 |
| 环境 / 数据 | 登录失效、前置数据缺失、接口 502、功能未部署到测试环境 | 标「⚠️ 阻塞」，写清需要补什么；缺数据写对应 D-xx |
| 环境偶发 | 接口超时（`ERR_TIMED_OUT`）、5xx、网关错误、页面白屏，且请求本身合法 | 刷新页面重做该步骤 **1 次**：恢复 → 按重做结果判定，在「环境备注」记一行（接口、现象、证据日志）；仍失败 → 标「⚠️ 阻塞：环境」。偶发导致的界面表现（如下拉为空且无失败提示）记「附带发现」，不计缺陷 |
| 产品缺陷 | 行为与预期不符、报错、接口业务失败 | 标「❌」，按下方「前后端初判」归属 |
| 需求不一致 | 实现与 PRD 正文写明的字段 / 列 / 规则不同（如 PRD 一个地址字段，实现拆成省市区三级必选）；页面本身没报错 | 标「❌ 需求不一致」，写清「PRD 原文 vs 实际」；不做前后端初判；由产品决定改实现还是改 PRD |

产品缺陷的前后端初判：🔴 **只用 S4 已抓到的接口证据判断，不查 SLS 日志、不读代码、不为此追加操作**（开发拿到接口路径 + 请求体 + 响应，自己排查更快）：

| 已有证据 | 初判 |
|---|---|
| 请求和响应都正常，但页面表现不对 | 前端 |
| 接口报错或返回业务失败 | 后端，附响应里的报错信息（message / biz_code） |
| 非法数据被接口接收（返回成功） | 前端 + 后端 |
| 光看接口证据判断不了 | 前后端待定，附接口证据，不再追查 |

改法建议只按现象给方向，不做代码定位。

🔴 判定为 ❌ 前，再确认一次预期来源：预期的依据是原文摘录 / 已回答的待确认项吗？来自默认规则的写「❌（基于默认规则 R-x.x）」；来自未经确认的默认假设的写「❌（基于假设 Q-xx，需确认需求）」。
