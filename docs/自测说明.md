# dsCli 自测说明

> 对应 xCode《老项目自动化测试标准》v1.0。规则和协议见 [测试规范](测试规范.md)，机器可读的配置见根目录 `xcode.yaml`、`xcode.json`。
> 最后更新：2026-11-09　｜　维护人：张永

## 1. 环境要求

| 工具 | 版本 | 说明 |
|---|---|---|
| Node.js | ≥ 24.9（实测 24.14） | 上游 DSH 的要求 |
| pnpm | 11.x（实测 11.28.5） | 装依赖、构建 |
| 操作系统 | Windows 10/11（主要）；macOS、Linux 也可以 | 验收测试经 `cmd` 调用 `code\bin\dsCli.cmd` |

不需要数据库、Redis、端口配置。全量测试**不需要任何密钥、不联网**。

只有 e2e 需要的环境变量（值放本机环境变量或被 git 忽略的 `info.txt`）：

| 变量 | 用途 |
|---|---|
| `DEEPSEEK_API_KEY` | 真实模型密钥 |
| `DEEPSEEK_BASE_URL` | 可选，模型网关地址 |

## 2. 一次性准备

```bat
pnpm -C code install --frozen-lockfile
pnpm -C code run build
```

依赖没变就不用重装。验收测试 TC-01、TC-02 发现没装或没构建时，也会自动执行这两步。

## 3. 沙箱

不需要单独启动。每个验收用例自己建一个临时目录（`%TEMP%\dscli-<用例>-<XCODE_SANDBOX>-*`），里面放 `DSH_HOME`、工作目录和会话文件；模型由本机模型桩提供，监听 `127.0.0.1` 的随机端口。多份副本可以同时跑，互不影响。用例结束后临时目录自动删除。

测试进程会清掉继承来的 `DEEPSEEK_*`、`ANTHROPIC_*`、`DSCLI_*`、`DSH_*`、`CLAUDE_CODE_*` 变量，不会用到本机的真实密钥。

## 4. 单元自测

| 范围 | 命令 | 用例数 | 耗时 |
|---|---|---|---|
| 输出协议自检 | `node tests\run.mjs protocol` | 4 项 | 1 秒 |
| dsCli 单元测试（vitest） | `node tests\run.mjs unit` | 3 | 约 5 秒 |

## 5. 验收测试（e2e）

覆盖的主流程（需求 #14，0.01）：

1. `-p` 非交互调用：位置参数和 stdin 输入，text / json / stream-json 输出，退出码。
2. 会话：`--session-id` 新建、`-r` 续接、续接不存在的会话时的报错。
3. 工具与权限：`--tools`、`--allowedTools`、`--disallowedTools`，各权限模式。
4. 配置：`dscli` profile 的配置树、`DSCLI_PATCH`、模型地址和密钥读取。

| 类型 | 命令 | 用例数 | 耗时 |
|---|---|---|---|
| 黑盒验收（模型桩） | `node tests\run.mjs acceptance` | 44 | 约 3 分钟 |
| 某个需求的验收 | `node tests\run.mjs acceptance --only req_<需求编号>` | — | — |
| 真实模型 e2e（手动） | `node tests\run.mjs e2e` | 0（暂无） | — |

**全量测试** `node tests\run.mjs`：2026-11-09 实测 193 秒。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| `unit > 依赖未安装` | 执行第 2 节的准备命令 |
| 验收用例报「dsCli 实现不存在」 | `code\apps\cli\lib\bin.js` 没有构建：`pnpm -C code run build` |
| 想看失败用例留下的现场 | 设 `DSCLI_KEEP_TEMP=1` 再跑，临时目录会保留，路径打印在 stderr |
| 只想重跑几条用例 | `node tests\run.mjs acceptance --grep "TC-1[24]"` |
| 本地服务连不上 | 开了代理时设 `NO_PROXY=127.0.0.1,localhost` |
| 输出里看不到 `✖` | 正常：协议规定失败行用 `✕`（见测试规范 4.1） |
